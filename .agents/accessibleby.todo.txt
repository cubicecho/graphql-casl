accessibleBy-style query helper — plan (Workstream B)
=====================================================
Status: DONE (2026-08). Shipped as `accessibleBy` in src/accessibleBy.ts.
Deferred follow-up to the GraphQLAbility work (see graphqlability.todo.txt).

What shipped
------------
accessibleBy(ability, action, subject, adapter?) -> filter | null.

  B1 ANSWERED — IN THIS LIBRARY, not a separate package. It needs no new
     dependency (the fold is ~30 lines over ability.rulesFor), and a package
     holding one function would cost consumers more than it saves. Framing: the
     library stays a GATE by default; this is an additive helper a resolver
     calls, not something applyPermissions does behind your back.
  B2 DONE, with one deviation. NOT built on rulesToQuery: that helper is
     `rulesToQuery` on @casl/ability 6 and was REPLACED by `rulesToCondition` /
     `rulesToAST` in 7 (verified against the installed v7 typings), and the peer
     range is >=6. The priority-flattening fold is implemented in-library
     instead, mirroring CASL's own algorithm: rules come back highest-priority
     first, so each `can` becomes an OR branch bounded by the `cannot`s that
     outrank it; an unconditioned `cannot` ends the walk, an unconditioned `can`
     means "everything, minus the bounds above it". A test cross-checks the
     filter against ability.can() row by row so the two cannot drift.
     null => deny-all, as planned.
  B3 DONE — the default AccessibleFilter<T> types its LEAVES against the
     subject's fields (MongoQuery<TSubjectMap[K]>), adding only the boolean
     operators around them. Subject names are constrained to keyof TSubjectMap.
  B4 DONE — test/accessibleBy.test.ts, 15 tests: deny-all, other-action,
     single rule, operators preserved, OR of several, allow-all, bounded
     allow-all, bounded branches, an outranked exclusion, an unconditioned
     exclusion from both directions, the row-by-row cross-check, and three
     adapter tests. Plus 3 integration tests in
     test/integration/permissions.integration.test.ts: a list resolver that
     fetches only the rows the caller may touch, an unconditioned rule, and the
     deny-all case (which never queries at all).
  B5 CONFIRMED but MOOT — no import from '@casl/ability/extra' at all, so no
     new peer dep and no import path to document. README + AGENTS.md updated.

  Q2 ANSWERED — free function, not a factory. TSubjectMap is inferred from the
     ability itself, so a factory would only repeat what the ability knows.
  Q3 ANSWERED — a FilterAdapter interface (rule/and/or/everything), defaulting
     to a mongo-style dialect since CASL conditions are already mongo-shaped. A
     Prisma-shaped adapter is five lines and is documented in the README rather
     than shipped, so the library stays free of data-layer opinions. Documented
     limit: an adapter controls the boolean SKELETON, not the leaf operators.

FOLLOW-UP (2026-08): accessibleBy assumes you OWN the resolver and can pass the
filter to your data layer. With a generated CRUD schema you do not — see
arg-scoping.todo.txt, which injects this filter into the field's own filter
argument instead, and which needs the FilterAdapter leaf hook this file
deliberately left out (Q3).

Motivation
----------
The library is GATE-ONLY today: a rule allows or denies a whole resolver/field.
It cannot do row/list-level filtering ("return only the notes this user may
read"). @casl/mongoose solves the equivalent for Mongoose via accessibleBy,
which is built on rulesToQuery from '@casl/ability/extra':

  - rulesToQuery(ability, action, subjectType, convert) folds matching rules into
    a query object: DIRECT rules -> $or (permissive), INVERTED rules -> $and of
    $not (restrictive). Returns null if the action is wholly disallowed on the
    subject type (caller should treat as "deny all" -> []).
  - @casl/mongoose's accessibleBy(ability).ofType('Post') returns a mongoose
    Query you can chain (.select/.limit/.sort).
  - Sequelize/other adapters supply their own `convert` (e.g. wrap inverted
    conditions in $not, symbolize operators).

GraphQL analog
--------------
Give a list/connection resolver a FILTER derived from the caller's ability
conditions, so it fetches only accessible rows instead of post-filtering.
